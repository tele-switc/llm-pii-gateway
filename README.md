# llm-pii-gateway

**面向企业与开发者的云端 LLM API 出网数据安全网关：中文敏感信息（PII）高精度识别、加密占位脱敏与 Fail-Closed 阻断护栏。**

---

在接入公有云大模型 API 时，企业和开发者面临数据安全与合规挑战。**llm-pii-gateway** 作为挂载于 LiteLLM 等大模型网关的前置安全护栏，提供中文强规则识别、Fernet 对称加密占位符保险箱、基于数据等级的智能路由及全链路不可逆审计日志。在识别到高危敏感信息时实行**故障即阻断（Fail-Closed）**，杜绝数据未经保护静默流出。

---

## 核心设计与防护机制

| 维度 | 传统方式 | 本网关方案 | 核心价值 |
|---|---|---|---|
| **合规依据** | 仅依赖服务商无留存口头承诺 | 建立出网前多级数据管控策略（D0～D3） | 主动防御，建立可核验的安全底线 |
| **规则适配** | 通用多语言库对中文规则适配不足 | 深度自建中文识别层（包含身份证校验位、全角字符、跨行数字、统一社会信用代码等） | 覆盖真实中文业务场景 |
| **控制策略** | 仅依赖提示词约定（Prompt 级约束） | 网关层强制拦截：按数据分级实施智能路由与安全阻断 | 协议层控制，模型侧无篡改可能 |
| **故障处理** | 检测模块异常时静默放行（Fail-Open） | 任何检测异常、超时或配置错误均立即阻断请求（Fail-Closed） | 彻底消除降级泄露盲区 |
| **审计留痕** | 缺乏针对出网文本的审计跟踪 | 每请求记录脱敏哈希与长度（不存原始明文），支持完整还原演练 | 满足合规复核与安全审计要求 |

---

## 数据分级与决策体系

系统将交互数据分为四级，并严格执行对应出网策略：

- **D0（公开数据）/ D1（普通内部数据）**：允许正常路由至云端模型服务。
- **D2（含 PII 敏感信息）**：经加密占位符脱敏后，仅允许分流至已签署无数据保留协议（ZDR）的合规供应商；模型返回时自动还原。
- **D3（核心凭据、病案与绝密资产）**：网关层直接执行 `DENY` 阻断，严禁任何形式出网。未携带有效分级标签的内容默认遵循 D3 策略处理。

## 系统组件

| 模块 | 核心职责 |
|---|---|
| `gateway/pii_guardrail.py` | LiteLLM 回调护栏：执行实体检测、数据分级评定、智能路由与 Fail-Closed 阻断 |
| `recognizers/cn_recognizers.py` | 中文强规则检测：身份证（包含 18 位校验算法）、手机、银行卡、统一社会信用代码、邮箱等 |
| `recognizers/zh_ner.py` | 姓名、地址、结构化病历号等扩展实体识别与上下文规则推断 |
| `gateway/vault.py` | 实体映射保险箱：基于 Fernet 加密持久化存储原始敏感字段与安全占位符映射 |
| `gateway/bypass.py` | 旁路安全防护：APM 脱敏、请求缓存哈希、SSE 流式分片还原与非扫描字段强制阻断 |
| `audit/` | 零明文留存的高性能 JSONL 审计模块与还原演练链路 |

## 快速开始

```bash
# 1. 安装核心依赖
pip install cryptography
pip install spacy && python -m spacy download zh_core_web_sm   # 可选：增强实体识别
pip install litellm                                           # 部署网关时安装

# 2. 运行全量单元测试套件（包含 103 项测试，无需网络与外部 API）
python -m pytest tests -q

# 3. 运行本地基准评测验证
python poc/run_gateway_test.py --tool presidio-zh --mode scan-only \
    --corpus corpus/zh_v1.jsonl --report out/presidio-zh.json

# 4. 启动安全网关服务
export NVIDIA_API_KEY=...  OPENROUTER_API_KEY=...  LITELLM_MASTER_KEY=...
litellm --config gateway/config.yaml --port 4000
```

## 凭据与安全规范

- 仓库内**零凭据**：绝不包含任何真实 API Key、私钥或生产证书，配置项统一遵循环境变量注入规范（`os.environ/...`）。
- 运行时生成的敏感加解密秘钥文件（`vault/*.key`）及审计日志均已纳入 `.gitignore` 安全隔离。
